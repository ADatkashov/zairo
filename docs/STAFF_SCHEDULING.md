# Сотрудники: график, выбор мастера, форс-мажор, цена

Статус: **решения согласованы, кода нет** (2026-10-06). Документ — спецификация перед реализацией.
Уже сделано до этого (PR #154, #155): личный кабинет сотрудника — несколько мест работы,
свои записи, принять/завершить/не пришёл, рейтинг.

## 1. Принципы

1. **Платит владелец бизнеса, поэтому удобство — его.** График и правила задаёт владелец.
   Сотруднику график не доверяем.
2. **Клиент никогда не видит мастера, которого в это время нет.** Время у мастера показывается
   только если он реально работает и свободен.
3. **Клиент принадлежит бизнесу, а не мастеру.** Запись оформляется на салон; мастер — предпочтение.
4. **Форс-мажор не должен терять деньги.** Запись по возможности переходит к другому мастеру.
5. **Работать в нескольких бизнесах нельзя запретить.** Нельзя только продать одно и то же время дважды.

## 2. Принятые решения

| № | Решение |
|---|---|
| 1 | График сотрудника задаёт **только владелец**. Сотрудник может лишь закрыть себе доступность («заболел», «не смогу»); расширить её не может. |
| 2 | Отмена записи сотрудником — это **запрос владельцу**, а не отмена с возвратом денег. |
| 3 | «Любой мастер» — клиенту переназначаем **молча** (с уведомлением). Если клиент выбрал **конкретного** мастера — решает сам клиент. |
| 4 | «Завершить» и «не пришёл» отмечает **сотрудник** (клиентов знает он, а не владелец). Владелец видит эти отметки и может их исправить. |
| 5 | У владельца есть настройка **«клиент может выбирать мастера»** вкл/выкл. |
| 6 | **Цена по мастерам** — решает владелец (раздел 7). По умолчанию выключено, все по базовой цене. |

## 3. График мастера

- По умолчанию мастер работает, когда открыт салон. Владелец правит только исключения:
  выходной, болезнь, отпуск, другая смена. Недельный шаблон на мастера задаётся один раз.
- Владелец каждого бизнеса задаёт график **только в своём бизнесе**. Пример: в одном 9–13,
  в другом 14–18 — независимо.
- **Один человек в двух бизнесах:** запись, оформленная первой, занимает это время у человека
  везде. Время в другом бизнесе просто перестаёт быть доступным.
- **Приватность:** владелец не видит, где ещё работает человек и у кого. Он видит только
  «занят в это время».

## 4. Выбор мастера клиентом

- Если у владельца включено «выбор мастера» — клиент выбирает конкретного мастера или «любой».
  По умолчанию предлагаем «любой».
- Запись помнит: `SPECIFIC` (выбрал мастера) или `ANY` (любой).
- При `ANY` мастера назначает система; автоназначение никогда не выбирает мастера с наценкой (раздел 7).

## 5. Форс-мажор

Владелец отмечает «мастера нет» (период или «сегодня»). Система показывает затронутые записи.

| Запись | Что происходит |
|---|---|
| `ANY` | Переназначается на свободного мастера с этой услугой; клиенту уведомление «мастер изменился». |
| `SPECIFIC` | Клиент выбирает: замена мастера с тем же временем, тот же мастер в ближайшее время, или отмена с возвратом. |

- Клиент не ответил — запись в списке «нужно решить» у владельца, с телефоном клиента.
- Клиент уже в салоне — владелец переназначает в один тап без согласования.
- Увольнение/отключение мастера запускает тот же поток для его будущих записей.
- **Ранний сигнал:** запись, которую мастер не принял за N часов до визита, попадает владельцу
  как предупреждение. Кнопка «принять» (уже есть) становится ранним индикатором.

## 6. Что сотрудник может и не может

| Действие | Сотрудник |
|---|---|
| Видеть свои записи в каждом бизнесе, рейтинг | да |
| «Принять» запись | да (подтверждение, статус брони не меняется) |
| «Завершить» / «не пришёл» | да, владелец видит и может исправить |
| «Не смогу» вместо отмены | да — запрос владельцу |
| Отменить запись с возвратом | **нет** (меняем текущее поведение кабинета) |
| Задавать или расширять свой график | **нет** |
| Закрыть себе доступность («заболел») | да, сразу закрывает новые записи и зовёт владельца |

## 7. Цена по мастерам

- Настройка бизнеса: переключатель **«разная цена у мастеров»**, по умолчанию **выключен**.
- Когда включён: владелец точечно задаёт цену услуги у конкретного мастера (поле поверх базовой цены).
- Клиент **не видит метки «платный»**: он просто видит свою цену, когда выбирает этого мастера.
  Цена всегда показывается до подтверждения брони.
- «Любой мастер»: клиент платит базовую цену; мастера с отличающейся ценой автоматически не назначаются.
- Цена фиксируется в момент записи.
- При переназначении (раздел 5) клиент **никогда не платит больше, чем согласился**:
  замена дешевле — цена снижается, разница возвращается; замена дороже — остаётся согласованная
  цена, разницу берёт на себя бизнес.

## 8. Как это ляжет на код (для разработки)

Подход выбран, чтобы переиспользовать то, что уже есть, а не строить параллельную систему:

- Слот остаётся единицей брони с атомарным захватом `OPEN → BOOKED`. Из недельного шаблона мастера
  система **сама** генерирует слоты мастера (`availability_slot.employee_id`) на скользящее окно
  (существующий `RecurringScheduleService` умеет это по `employeeId`). Владелец больше не строит
  расписание по людям руками.
- Исключения (болезнь, отпуск) закрывают `OPEN`-слоты мастера; занятые (`BOOKED`) не трогаются — они
  идут в поток форс-мажора.
- Занятость в другом бизнесе: по `staff.user_id` ищем пересечения броней; при создании брони проверяем
  повторно под блокировкой по `user_id`, чтобы две одновременные записи не прошли.
- Цена: поле цены мастера у связки мастер–услуга (`staff_service`); `BookingService.createBooking`
  сейчас берёт цену только из услуги и должен брать её из связки.
- Новые настройки бизнеса: «клиент выбирает мастера», «разная цена у мастеров».
- Новые поля/таблицы: недельный график мастера, исключения мастера, `SPECIFIC/ANY` в записи,
  признак «клиент ответил» для форс-мажора.
- Кабинет сотрудника: «отменить» превращается в «не смогу»; владельцу — экран графика, «мастера нет»,
  список «нужно решить», переназначение записи.

## 9. Проверить перед реализацией

- Частичный возврат при снижении цены: у `PaymentRefundRequest` есть сумма, но поддерживается ли
  частичный возврат у провайдера платежей — не проверено.
- Окно генерации слотов и что делать с уже созданными общими слотами бизнесов, где мастера появятся позже.
- Исправление владельцем ошибочной отметки «завершено»: сейчас статус `COMPLETED` необратим,
  а он запускает баллы лояльности и право на отзыв.
- Время в пути между бизнесами (буфер) — пока не учитываем.

## 10. Порядок работ

1. График мастера у владельца + «мастера нет» + защита от двойной записи + выбор мастера клиентом.
2. Переназначение и выбор клиента при отсутствии мастера; «не смогу» вместо отмены у сотрудника.
3. Цена по мастерам.
4. Предупреждение о непринятых записях и исправление отметок владельцем.
