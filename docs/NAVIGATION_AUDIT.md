# Аудит навигации и UX-удобства (user_app + business_admin)

Дата: 2026-10-04. Только анализ — код приложений не менялся.
Ссылки вида `файл:строка` указывают на место в коде на момент аудита.

## 1. Как навигация устроена сейчас

**user_app** (go_router 18)
- Корневой роутер: `app/router/app_router.dart`. Всего **2 «настоящих» маршрута** верхнего уровня:
  `/city-selection` и `StatefulShellRoute.indexedStack` с 4 вкладками
  (`/`, `/search`, `/bookings`, `/profile`).
- Всё остальное (≈ 30 экранов: карточка провайдера, бронь, чат, уведомления,
  избранное, лояльность, авто, настройки, авторизация…) открывается через
  `Navigator.of(context).push(MaterialPageRoute(...))` — **~138 вызовов**,
  go_router об этих экранах ничего не знает.
- Нижняя панель `FactoryBottomNavigation` — плавающая «пилюля», 4 пункта.
  `MainWrapper` лежит **вне** навигатора ветки, поэтому панель остаётся видимой
  на всех запушенных экранах (карточка провайдера, чат, бронь).

**business_admin**
- Нет роутера (`auth_gate.dart`): `AuthGate` переключает Login ↔ главный экран.
- Desktop: `AdminShell` с боковой панелью (7 разделов, `IndexedStack`).
- Mobile/tablet: `DashboardScreen` с **6 иконками в AppBar** + линейный push.

## 2. Критичные проблемы (ломают сценарии)

### P1. Логин сбрасывает пользователя в корень вкладки и теряет контекст
`popUntil((route) => route.isFirst)` после входа
(`login_screen.dart:231`, `otp_screen.dart:182`, `phone_otp_password_screen.dart:171`,
`phone_password_screen.dart:104`, `register_screen.dart:42`).
Сценарий: гость открыл карточку мастера → выбрал услугу и слот → «Записаться» →
экран логина → вошёл → **выброшен на корень вкладки**, выбор услуги/слота потерян
(`provider_detail_screen.dart:502`). То же с ♥ (`favorite_button.dart:36`) и
«Написать» (`provider_detail_screen.dart:459`).
**Нужно:** после входа делать `pop()` одного экрана логина (или «возврат на
исходный маршрут») и продолжать отложенное действие автоматически.

### P2. Экран подтверждения брони: кнопки ведут не туда
`booking_confirmation_screen.dart:142-154`
- «Мои записи» делает `pushAndRemoveUntil(MyBookingsScreen)` — это **вторая копия**
  экрана записей внутри текущей ветки, а не переход на вкладку «Записи»;
  подсвечена остаётся вкладка Home/Search, а не Bookings.
- «На главную» делает `popUntil(isFirst)` — возвращает на корень **той ветки,
  откуда начали** (если бронировали из Поиска — останетесь в Поиске, не на Главной).
**Нужно:** `context.go('/bookings')` и `context.go('/')`.

### P3. Уведомления «мёртвые»
`notifications_screen.dart` (тап по плитке): только `markRead`, переход к
записи/чату не выполняется, у прочитанных `onTap == null`. Уведомление
«Запись подтверждена/отменена/напоминание» должно открывать соответствующую запись.

### P4. Нет deep links и восстановления состояния
Из-за `MaterialPageRoute` у экранов нет URL/пути: на web нельзя поделиться ссылкой
на мастера, обновление страницы сбрасывает всё на вкладку; нет открытия из
push-уведомления/SMS/QR; в Android/iOS-манифестах нет app-links/universal links
(только схема Facebook). Для маркетплейса записи ссылка «забронировать у мастера»
— базовая функция.

### P5. Кнопка «Назад» (Android) и системные жесты не продуманы
Во всём `user_app` нет ни одного `PopScope`. Последствия:
- Из корня любой вкладки системное «назад» **закрывает приложение**, а не
  возвращает на Главную (Android-стандарт для tab-приложений).
- На шаге оплаты/брони (`_isBooking == true`) назад можно уйти посреди запроса.
- Незавершённые формы (отзыв, сообщение, фильтры) закрываются без предупреждения.

## 5. Карта «где что лежит» (для проверки глубины)

```
Home ─ город ─ уведомления ─ все категории ─ карточка провайдера ─┬─ карта
 │                                                                ├─ мастер → портфолио → просмотр
 │                                                                ├─ лояльность → история
 │                                                                ├─ чат (логин-гейт)
 │                                                                └─ запись → подтверждение
Search ─ фильтры(sheet) ─ карточка провайдера
Bookings ─ карточка брони ─ чат / отмена / отзыв
Profile ─ настройки → безопасность → привязка телефона
        ├ избранное (глубина 2)     ├ сообщения → чат
        ├ бонусы → бизнес-лояльность └ купоны / авто / поддержка / о приложении
(не достижим) ServiceCompareScreen
```
Глубина «забронировать» с Главной: Home → карточка → (логин) → подтверждение = 3–4 экрана;
«Избранное» и «Купоны» = 3 тапа от любой вкладки.

## 6. План улучшений (по приоритету)

**Этап 1 — исправление багов навигации (малый риск, большой эффект)**
1. После логина — возврат на исходный экран и автоматическое продолжение действия
   (P1); универсальный `requireAuth(context, ref, then: ...)`.
2. Исправить кнопки подтверждения брони → `context.go('/bookings')`, `context.go('/')` (P2).
3. `PopScope` на корне вкладок: назад → Главная → выход; подтверждение на незавершённых формах (P5).
4. Подтверждение выхода (U7); убрать `logout` из AppBar админки в меню профиля.
5. Подключить `ServiceCompareScreen` (кнопка «Сравнить цены» на карточке услуги/в поиске) или удалить (U1).

**Этап 2 — перевод на go_router (фундамент)**
6. Описать вложенные маршруты: `/provider/:id`, `/provider/:id/book`, `/booking/:id`,
   `/chat/:providerId`, `/notifications`, `/favorites`, `/loyalty/...`, `/settings/...`,
   `/login` (+ `?redirect=`). Заменить `Navigator.push` на `context.push`.
7. Решить, какие экраны открывать поверх оболочки (без нижней панели): детальные/
   платёжные/полноэкранные — через `parentNavigatorKey: rootNavigatorKey` (U11).
8. Deep links (Android App Links, iOS Universal Links) + web-URL; переход из
   push-уведомлений на запись/чат (P3, P4).

**Этап 3 — улучшение сценариев**
9. Поиск: убрать `autofocus`, live-подсказки, очистка, «Сбросить фильтры», перенос
   категории/запроса с Главной (U2, U3); тап по активной вкладке → скролл вверх (U4).
10. Профиль: группы (Активность / Аккаунт / Помощь), бейджи, колокольчик на всех
    вкладках, Избранное — отдельной видимой точкой входа (U5, U6).
11. Записи: CTA в пустом состоянии, «Повторить», в календарь/маршрут после брони (U8, U9).
12. Первый запуск: выбор города/геолокации как онбординг-шаг (U10).
13. Единый шаговый индикатор для цепочки авторизации (U13).

**Этап 4 — business_admin**
14. Нижняя навигация на mobile (Дашборд / Записи / Сообщения / Клиенты / Ещё) вместо
    6 иконок; общий `NavigationDestination`-список с desktop-сайдбаром (A1, A2).
15. go_router + deep links (A3), бейджи (A2), быстрые действия/поиск (A5).

## 8. Статус внедрения

**Этап 1 (2026-10-04)** — сделано в коде, без запуска на устройстве/CI-прогона локально (во Flutter-SDK в cloud-сессии нет):
- P1: `auth_navigation.dart` (`pushAuthScreen` / `popAuthFlow`) — после входа возврат на экран, с которого открыли логин; цепочка помечена именем маршрута. Заказ не отправляется автоматически — пользователь нажимает «Записаться» ещё раз.
- P2: кнопки подтверждения брони переключают вкладки (`/bookings`, `/`) и обновляют список записей.
- P5: `PopScope` в `MainWrapper` (назад из вкладки → Главная → выход) и блок «назад» на карточке провайдера во время отправки брони.
- U7: подтверждение выхода в профиле, Dashboard и Moderation админки (строки en/ru/kk).
- Не сделано: U1 (`ServiceCompareScreen` — подключить или удалить, нужно продуктовое решение), PopScope на формах с несохранёнными данными.

**Этап 2 (2026-10-04), часть 1** — маршруты go_router (проверено `flutter analyze` и `flutter test`):
- `app/router/app_routes.dart` (`AppRoutes`) + новые корневые маршруты: `/provider/:id`, `/notifications`, `/favorites`, `/messages`, `/messages/:providerId?name=`, `/loyalty/:providerId?name=`, `/rewards`, `/redemptions`, `/vehicles`, `/support`, `/about`, `/settings`, `/settings/security`.
- Эти экраны открываются поверх оболочки вкладок (`parentNavigatorKey: rootNavigatorKey`), нижняя панель на них не рисуется (U11), вкладка под ними сохраняет состояние.
- `/provider/:id` без `extra` (ссылка, обновление web-страницы) находит провайдера в общем поиске; отдельного эндпоинта «провайдер по id» в поиске пока нет — стоит добавить на бэкенде.
- Цепочка авторизации открывается на корневом навигаторе (без нижней панели), без собственных URL — это временный сценарий.
- Не переведено на маршруты (нужны объекты в аргументах): экран подтверждения брони, карта, портфолио мастера, редактирование профиля, чат из бронирований уже через `/messages/...`.
- Не сделано: Android App Links / iOS Universal Links (нужен домен и `assetlinks.json` / `apple-app-site-association`), переходы из push-уведомлений (P3), этапы 3–4.

**Этап 3 (2026-10-04), часть 1** — сценарии (проверено `flutter analyze` и `flutter test`):
- U2: «Все / Поиск» на Главной открывают `/search?category=…`; Поиск применяет категорию и при повторном заходе (`didUpdateWidget`).
- U3: у Поиска убран `autofocus` (клавиатура больше не закрывает «Недавние/Популярные»); в `FactorySearchField` добавлена кнопка очистки (`onCleared`); в пустой выдаче есть «Сбросить поиск и фильтры».
- U4: повторный тап по активной вкладке возвращает к корню и прокручивает вверх (`tabReselectProvider` + `ScrollToTopOnTabReselect`).
- U5/U6: Профиль разбит на группы «Моя активность» / «Помощь», «Избранное» есть отдельной строкой списка.
- U8: пустые «Записи» с кнопкой «Найти услугу»; у вкладок «Предстоящие / Завершённые / Отменённые» свои заголовки и тексты.
