# Промт для Claude Design

Вставить целиком в Claude Design (с подключённым репозиторием `adatkashov/zairo`, ветка `develop`).

---

## Контекст

Flutter-монорепо (Material 3, go_router, Riverpod) с тремя приложениями и общей дизайн-системой `packages/core_ui`. Языки: RU / KK / EN. Светлая и тёмная темы настроены отдельно, не инверсией.

## Роль

Ты старший продуктовый дизайнер уровня Airbnb, Linear, Stripe и Revolut. Нужно поднять дизайн платформы до уровня лучших приложений 2026 года, не ломая функциональность. Три приложения должны ощущаться как одна семья, но у каждого своя аудитория:

| Приложение | Аудитория | Характер |
|---|---|---|
| `apps/user_app` | клиенты, mobile-first | тёплый, фото-first, запись в 2–3 тапа |
| `apps/business_admin` | владельцы и персонал, телефон между клиентами, планшет | рабочий и ясный, быстрые действия |
| `apps/platform_admin` | сотрудники платформы, в основном web | плотный и аналитический, как Stripe Dashboard |

## Что уже сделано, не переделывай с нуля

- Токены и ~35 виджетов `Factory*` в `core_ui`, включая `FactoryPaymentBreakdown`, `FactoryBottomNavigation`, skeleton, empty/error-состояния.
- Локализация на 3 языках с проверкой паритета ключей в CI.
- Адаптивные оболочки: в `platform_admin` bottom bar до 768px, rail 768–1199, sidebar от 1200 (`FactoryBreakpoints`).
- В `platform_admin` уже есть command palette, массовые действия и сохранённые фильтры.
- Недавно добавлено: экран бизнеса разбит на 5 вкладок (Обзор, Услуги, Команда, Записи, Настройки), таблица бизнесов сортируется по столбцам, добавлены темы для вкладок, переключателей и прогресса.

## Что нужно сделать

1. Оцени текущий вид по коду. Для каждого приложения найди 5–10 реальных проблем: иерархия, плотность, пустые и ошибочные состояния, расхождения между приложениями.
2. Предложи единое направление и осознанные различия между приложениями. Любое изменение токенов обоснуй. Сейчас в светлой теме фон `#F7F6F3`, основной цвет Pine `#1B5C52` (в тёмной `#4FCFB4`), акцент Gold `#C99A3E`. Шрифты: Unbounded для заголовков, Golos Text для интерфейса, JetBrains Mono для цен и времени.
3. Особое внимание этим местам:
   - **user_app:** `home_screen`, `search_screen` и `provider_detail_screen` (1286 строк, перегружен); путь «услуга → время → оплата → подтверждение»; прозрачность оплаты (всего, депозит, остаток); экран «Мои записи» с историей платежей.
   - **business_admin:** `dashboard_screen` (одна главная метрика, остальные вторичны); календарь записей; настройки депозита; плотные списки вместо сетки крупных карточек.
   - **platform_admin:** таблицы с пагинацией, фильтрами и панелью деталей; страница финансов (выплаты, возвраты); журнал действий.
4. Современные приёмы, но без перегиба:
   - Bento-сетки только для дашбордов.
   - Тонкие границы 1px и мягкие тени; blur только для навигации и оверлеев.
   - Крупные цифры с tabular-шрифтом, sparklines, тренд-бейджи.
   - Микроанимации с учётом reduce motion; skeleton вместо спиннеров.
   - Контраст не ниже 4.5:1, цели касания не менее 44px, видимый фокус, масштабирование шрифта.
   - Статус никогда не передаётся одним цветом.
5. Никаких выдуманных метрик и кнопок, которые ничего не делают. Если нужной функции в бэкенде нет, нарисуй честное состояние и пометь это.

## Ограничения

- Только то, что собирается виджетами Flutter поверх `core_ui`. Изменения общих токенов и компонентов делаются в `core_ui` один раз для всех приложений.
- Не менять бизнес-логику, маршруты и API.
- Никаких хардкод-строк: тексты через `l10n/app_{ru,kk,en}.arb`. Учитывай длину RU и KK.
- Работает для всех вертикалей (beauty, auto, cleaning) и для новых.
- Без тяжёлых blur и шейдеров в длинных списках.

## Формат ответа

1. Ревизия по трём приложениям.
2. Дизайн-направление: общее и различия, с референсами.
3. Токены и компоненты `core_ui` с точными значениями и состояниями (default, pressed, focused, disabled, loading, error).
4. Макеты ключевых экранов: user_app 390px; business_admin 390 / 834 / 1440; platform_admin 1440 / 834 / 390.
5. План внедрения для Claude Code по шагам: `core_ui`, затем user_app, затем business_admin, затем platform_admin. Каждый шаг должен проходить `flutter analyze` и `flutter test`.
