# Промт для Claude Design — редизайн Business Platform (apps/business_admin)

Вставить целиком в Claude Design (с подключённым репозиторием `adatkashov/zairo`, ветка `develop`).

---

## Роль

Ты — senior product designer уровня Linear / Stripe Dashboard / Vercel / Notion / Apple. Тебе доступен код репозитория и текущий дизайн. Задача — **довести дизайн Business Platform до уровня самых трендовых, популярных и красивых B2B/SaaS-продуктов 2026 года**, не ломая существующую функциональность.

## Контекст продукта

Business Platform — приложение для владельцев и модераторов бизнеса (салоны красоты, автомастерские; позже другие вертикали): `apps/business_admin` (Flutter, Material 3, go_router, Riverpod). Работает на телефоне (основной сценарий — владелец с телефона между клиентами), планшете и web. Языки: RU / KK / EN (тексты бывают длинными — дизайн должен это выдерживать). Светлая и тёмная темы обязательны.

Разделы (`apps/business_admin/lib/features/`): dashboard, salon, beauty, auto, catalog, staff, messaging, reviews, loyalty, campaigns, automation, billing, moderation, city, settings, storage, auth.

Общая дизайн-система: `packages/core_ui` (tokens: `factory_colors`, `factory_typography`, `factory_spacing`, `factory_radius`, `factory_elevation`, `factory_motion`; виджеты `Factory*`). Описание: `docs/design-review/FACTORY_DESIGN_SYSTEM.md`, замечания: `docs/design-review/AUDIT_FINDINGS.md`. Сейчас: тёплый stone-нейтральный фон `#F7F6F3`, primary Pine `#1B5C52` (dark: `#4FCFB4`), акцент Gold `#C99A3E`, шрифты Unbounded (заголовки) + Golos Text (UI) + JetBrains Mono (цифры).

## Что сделать

1. **Изучи код и текущий вид** всех основных экранов (в первую очередь: dashboard, календарь/записи, клиенты, сотрудники, каталог услуг, сообщения, отзывы, лояльность/кампании, биллинг, настройки, онбординг/логин).
2. **Проведи ревизию**: что выглядит устаревшим, перегруженным, непоследовательным, где слабая иерархия, плотность, пустые/ошибочные/загрузочные состояния.
3. **Предложи и опиши улучшенную визуальную систему**, опираясь на актуальные тренды (используй их осознанно, без перегиба):
   - чистый минимализм с сильной типографской иерархией, много воздуха, но высокая информационная плотность там, где это работа (таблицы, календарь);
   - **Bento-сетки** для дашборда: карточки разного размера, одна «героическая» метрика, остальные вторичны;
   - мягкие многослойные поверхности, тонкие 1px-границы + деликатные тени, аккуратный glass/blur только для навигации и оверлеев;
   - современные градиенты и «ambient glow» в акцентных местах, не залитые градиентом экраны;
   - крупные числа (tabular), микро-графики (sparklines), прогресс-кольца, тренд-бейджи (▲ +12%);
   - скругления 16–24 для карточек, 12 для контролов, единая сетка 4/8pt;
   - микроанимации и переходы (staggered reveal, shared-element, skeleton → контент, haptics-friendly press states), уважающие `reduce motion`;
   - Command palette / быстрый поиск, быстрые действия (FAB / quick-add), swipe-действия на мобильном;
   - продуманные empty states с иллюстрацией и CTA, понятные error states;
   - dark mode — отдельно настроенный, не инверсия; глубокие тёплые тона, свечение вместо теней;
   - доступность: контраст ≥ 4.5:1, цель касания ≥ 44px, фокус-состояния, масштабирование шрифта.
4. **Сохрани бренд-основу** (Pine + Gold + stone), но можешь пересобрать палитру, шкалу типографики и компоненты, если это даёт заметно лучший результат. Любое изменение токенов обосновывай.
5. **Выдай результат в виде, пригодном для реализации во Flutter**:
   - обновлённые токены (цвета light/dark, типографика, spacing, radius, elevation, motion) — с точными значениями;
   - список компонентов `core_ui` для изменения/создания (с состояниями: default / hover / pressed / focused / disabled / loading / error);
   - макеты ключевых экранов в mobile (390px), tablet (834px) и desktop (1440px) вариантах;
   - приоритезированный план внедрения: сначала токены и базовые компоненты, затем dashboard, затем остальные разделы.

## Ограничения

- Реализация будет во Flutter/Material 3 поверх `packages/core_ui` — не предлагай то, что нельзя разумно собрать виджетами (никаких React-only решений в финальных спецификациях).
- Не менять бизнес-логику, маршруты и API.
- Все строки уже локализованы (`l10n/app_{ru,kk,en}.arb`) — не хардкодь текст в макетах, учитывай длину RU/KK.
- Дизайн должен работать для обеих вертикалей (beauty, auto) и расширяться на новые.
- Производительность: без тяжёлых blur/шейдеров на длинных списках.

## Формат ответа

1. Краткая ревизия текущего состояния (5–10 пунктов).
2. Дизайн-направление в 1 абзац + moodboard-описание (референсы: Linear, Stripe, Vercel, Arc, Apple Health, Revolut Business, Mercury).
3. Токены и компоненты (таблицы).
4. Макеты экранов.
5. План внедрения по шагам, чтобы Claude Code мог последовательно закодить результат.
