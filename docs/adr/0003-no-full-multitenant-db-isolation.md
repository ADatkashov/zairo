# ADR-0003: Без полной multi-tenant изоляции БД

## Статус
Принято — 2026-08-19

## Контекст
Платформа задумана так, что в будущем на её базе могут запускаться разные
vertical-приложения (Beauty, Auto, ...), возможно принадлежащие разным
заказчикам/брендам. Модель данных (см. `docs/erd/core-domain.md`) уже
разделяет Core-сущности и vertical-специфичные расширения.

## Решение
На старте — одна общая база PostgreSQL, без schema-per-tenant и без
row-level security (RLS) по tenant/vertical. Изоляция между vertical'ами
обеспечивается на уровне кода/модулей (Core не читает и не пишет
vertical-таблицы напрямую), а не на уровне СУБД.

## Почему
- Ещё нет второго реального vertical и тем более второго независимого
  tenant — проектировать изоляцию сейчас означало бы гадать на будущих
  требованиях, которых нет.
- `PROVIDER.vertical` как непрозрачная строка (см. ERD) уже даёт логическое
  разделение данных без необходимости физической изоляции.
- Добавление schema-per-tenant/RLS позже — это миграция на уровне
  инфраструктуры БД, не переписывание доменной модели, если границы модулей
  соблюдались с самого начала.

## Когда пересматривать
Как только появится второй vertical (Auto, Phase 9) или конкретное
требование от заказчика на изоляцию данных (комплаенс, контракт) —
тогда выбирается конкретная стратегия (schema-per-tenant, RLS, отдельные БД)
исходя из реального требования, а не заранее.

## Альтернативы
- Schema-per-tenant с первого дня — отклонено: инфраструктурная сложность
  без текущего потребителя.
- Отдельная БД на vertical — отклонено по той же причине.
