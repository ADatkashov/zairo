# Консоль платформы (`apps/platform_admin`)

Отдельное приложение для сотрудников ZAIRO. Раньше «Platform Admin» был
спрятан за текстовой кнопкой на экране входа `business_admin`: код консоли
ехал на телефоны всех владельцев бизнеса. Теперь это самостоятельное
приложение со своим входом, своей сборкой и своим деплоем.

Дата: 2026-10-05. Бэкенд при этом **не менялся** — приложение использует
только уже существующие эндпоинты `/api/v1/platform/**`.

## Где работает

Один код, шесть платформ: **web** (основной сценарий), **Android**, **iOS**,
**Windows**, **macOS**, **Linux**. Вёрстка адаптивная (`FactoryBreakpoints`):

| Ширина | Навигация |
|---|---|
| телефон (< 768) | нижняя панель из 5 пунктов: Обзор, Бизнесы, Каталог, Финансы, «Ещё» (Города, Журнал, Сотрудники, Настройки); системная «назад» из раздела «Ещё» возвращает в «Ещё», из остальных — на Обзор |
| планшет (768–1199) | узкая боковая колонка с иконками |
| десктоп (≥ 1200) | боковая панель с подписями и значками «требует внимания» |

Каждый раздел — это URL (`/businesses?status=PENDING`, `/finance?tab=refunds`):
ссылки открываются напрямую, обновление страницы в браузере остаётся на том же
разделе, а после входа человек попадает туда, куда шёл.

В сборку проверено: `flutter analyze`, `flutter test` (59 тестов, включая
проверку отсутствия overflow на 360 и 768 px на трёх языках) и
`flutter build web --release`. Нативные сборки (Android/iOS/desktop) в
CI-контейнере не собирались — их папки созданы стандартным `flutter create`;
Android-APK добавлен в CircleCI.

## Запуск и сборка

```bash
cd apps/platform_admin
flutter run -d chrome                       # против локального backend (localhost:8080)
flutter run -d chrome --dart-define=API_BASE_URL=https://api.example.com/api/v1
flutter build web --release --dart-define=API_BASE_URL=https://api.example.com/api/v1
```

**Деплой web:** `build/web` — обычная статика, кладётся на отдельный домен
(например `admin.…`). Два обязательных шага вне приложения:

1. На backend задать `CORS_ALLOWED_ORIGINS` с адресом консоли — по умолчанию
   разрешён только `http://localhost:*` (`WebConfig`).
2. SPA-fallback на `index.html` (чтобы прямые ссылки и обновление страницы не
   давали 404). В `index.html` уже стоит `noindex, nofollow`.

Желательно ограничить доступ к домену по VPN/IP — это внутренний инструмент.

## Что взято из user_app / business_admin, а что нет

Взято (адаптировано, не скопировано слепо):

| Откуда | Что |
|---|---|
| оба приложения | `core_ui` (тема, кнопки, карточки, чипы, диалоги, нижняя панель), `core_network`, `core_storage`, `core_region` не нужен |
| business_admin | go_router с URL-адресуемыми разделами, оболочка «боковая панель / рейка / нижняя панель», `PopScope` на телефоне, бейджи «требует внимания» в навигации |
| оба | переключатель языка (kk/ru/en) и темы с сохранением, экран входа с понятными ошибками, подтверждение выхода |
| business_admin | быстрые действия и поиск на дашборде → здесь «Требует внимания» со ссылками в нужный раздел и поиск/фильтры в каждом списке |
| прежняя консоль | модерация бизнесов, каталог, журнал, сотрудники, смена фото |

Сознательно **не** взято:

- Вход через Google/Apple/телефон/регистрация — у сотрудников один способ входа
  (email + пароль, `POST /platform/auth/login`), аккаунты создаёт администратор.
- Биометрия — у платформенного токена нет refresh-токена (см. ниже), нечего
  разблокировать.
- Сообщения, лояльность, кампании, подписки — это инструменты владельца бизнеса.
- Свой Dio без `LogInterceptor`: общий `dioProvider` логирует тела запросов и
  ответов, то есть пароли и токены попали бы в debug-лог.

## Что умеет консоль (по ролям)

| Раздел | Что внутри | Эндпоинты | Кто может менять |
|---|---|---|---|
| Обзор | что требует внимания (бизнесы на модерации, неудачные возвраты, выплаты к оплате), показатели | `GET /platform/dashboard`, `/platform/payouts` | — (чтение) |
| Бизнесы | поиск, фильтр по статусу, карточка с выплатами бизнеса, одобрить / приостановить (с причиной) / восстановить | `GET/PATCH /platform/businesses[/{id}/status]` | ADMIN, MODERATOR |
| Каталог | категории → сферы → подсферы → услуги: **создать, переименовать на 3 языках, поменять позицию и иконку, скрыть/показать**; код генерируется из английского названия | `GET/POST/PATCH /platform/{categories,business-types,subspheres,services}` | ADMIN |
| Города | список (в т.ч. скрытые), создать, изменить, скрыть, удалить; часовой пояс и валюта подставляются из страны | `GET /cities`, `GET /countries`, `POST/PUT/DELETE /platform/cities` | ADMIN |
| Финансы → Выплаты | очередь выплат бизнесам по статусам; «начать перевод», «выплачено» (с номером перевода), «не удалось» (с причиной) | `GET /platform/payouts`, `POST …/mark-*` | ADMIN |
| Финансы → Возвраты | платежи с неудачным возвратом, очередь возвратов по состояниям, **сверка платежа с провайдером** | `GET /platform/payments/{failed-refunds,refund-requests}`, `POST …/reconcile` | любая роль (сверка только читает) |
| Журнал | кто, что, над чем и «из → в»; фильтр по разделу, поиск, «показать ещё» | `GET /platform/audit-log` | — |
| Сотрудники | список, роли с пояснениями, добавить, отключить (с причиной) / включить | `GET/POST /platform/admins[/{id}/…]` | ADMIN |
| Настройки | профиль и фото, **что разрешено вашей роли**, язык, тема, адрес сервера | `PATCH /platform/auth/me/avatar`, `POST /platform/uploads` | — |

Кнопки, которые сервер всё равно отклонит (403), роли просто не показываются
(`PlatformPermissions` повторяет проверки `PlatformCurrentAdmin`). Прежняя
консоль показывала их всем, и модератор получал «что-то пошло не так».

Опасные действия подтверждаются (приостановка, скрытие из каталога/городов,
удаление города, отключение сотрудника, «выплачено», выход) и объясняют
последствия словами. Необратимое «выплачено» прямо говорит, что оно *фиксирует*
перевод, а не делает его.

## Сессия и безопасность

- Токен живёт 30 минут (`PlatformAdminJwtService`), refresh-токена нет. Токен
  хранится в `SecureStorageService`, чтобы обновление страницы не выкидывало на
  вход; при старте проверяются срок (`exp`) и `GET /platform/auth/me`.
- Любой 401 вне экрана входа = «сессия закончилась»: выход, экран входа с
  объяснением, и после нового входа человек возвращается на ту же страницу.
  Таймер выходит сам, не дожидаясь запроса.
- Пароль нигде не сохраняется; запоминается только последний email.

## Результаты анализа: чего не хватает (по убыванию важности)

**Противоречит требованию «бизнес не пишет услуги сам»**

1. `ServiceOfferingController` принимает свободное название услуги, а связь с
   каталогом (`PATCH /services/{id}/catalog-link`) **необязательна**. Пока это
   так, владелец может завести «Маникюр-2» мимо каталога, и всё управление
   каталогом в консоли — рекомендация, а не правило. Нужно: сделать
   `catalogServiceId` обязательным при создании услуги (бэкенд) и заменить
   текстовое поле на выбор из каталога в `business_admin` (отдельный PR).

**Безопасность входа сотрудников**

2. Нет ограничения попыток входа для `/platform/auth/login` (у обычного входа
   есть `LoginAttemptLimiter`) — перебор пароля сотрудника не ограничен.
3. Нет смены собственного пароля, сброса пароля сотруднику и 2FA; временный
   пароль, заданный при создании, остаётся навсегда, пока кто-то его не
   поменяет прямо в БД.
4. Нет refresh-токена: каждые 30 минут — новый вход, во время длинной
   модерации это раздражает. Нужен refresh (или скользящая сессия).
5. Роль сотрудника нельзя изменить (только отключить и создать заново).

**Операционные пробелы (в бэкенде нет эндпоинтов)**

6. Нет карточки бизнеса: контакты владельца, тариф и состояние подписки,
   услуги, мастера, отзывы. Сейчас в консоли id владельца и выплаты.
7. Нет списков пользователей, записей и платежей (кроме неудачных возвратов),
   нет модерации отзывов и кампаний, нет ручной смены тарифа бизнеса
   (в роадмапе: «admin plan assignment»).
8. Нет серверной фильтрации и пагинации журнала по типу/дате/сотруднику
   (фильтры в консоли работают по уже загруженным записям).
9. Дашборд — только текущие числа, без динамики по дням; нет разреза по
   городам.
10. Каталог: нет удаления и переноса между родителями (только скрыть) и нет
    массовой перестановки; позиция меняется числом.

**Дублирование контуров**

11. В `business_admin` остался `ModerationScreen` для роли `ADMIN` (старый
    контур). Он дублирует «Бизнесы» консоли, а его эндпоинт
    `PATCH /providers/{id}/status` не пишет в журнал. Рекомендация: перевести
    модерацию целиком в консоль и убрать legacy-роль.

## Тесты

`apps/platform_admin/test` — виджет-тесты поверх `FakeBackend` (подставной
`HttpClientAdapter`): настоящие API-классы, настоящие interceptors, без сети.
Покрыты вход / восстановление сессии / 401 / выход, оболочка на трёх ширинах,
каждый раздел с его действиями и ограничениями ролей, и проверка отсутствия
overflow на всех разделах в трёх языках.

```bash
cd apps/platform_admin && flutter test
```
